# 检索与筛选

## 品牌发现

1. 用品牌全名或公司全名找官网，优先打开关于、产品或服务、行业方案等页面。核对公司主体、品牌和产品线是否一致，记录官网 URL 及关键产品页面。官方资料足以判断时直接继续；重名且无法判断目标主体时，再请用户补官网或产品。官网不可确认时，使用能核验的其他公开资料并说明不确定性。
2. 提取产品或服务、目标人群、使用场景、购买或使用顾虑、经确认的简称或产品别名。用户提供产品线时按该范围查；品牌业务过宽时选与请求相关的代表产品线并说明范围。
3. 按同类产品、目标客户或相同使用任务找竞品，并保留能核实该关系的官网或可靠资料。双方仅同属一个宽行业时不足以归为竞品。无法核实具体名称时，搜同类产品或替代方案。
4. 查询覆盖三组词：品类或俗称加用户场景与疑问、主品牌及别名加产品或顾虑、竞品或替代方案加对比意图。每条查询集中于一个意图，避免整段产品描述直接入搜。

## 种子扩展

1. 保留种子原文并编号，例如 S01。拆出产品或对象、用户场景、问题意图和限定条件，合并重复种子的检索，但保留对应编号。用户给定的产品范围和竞品优先用于识别对象；只为缺失或歧义信息补查。
2. 对每个种子生成两类检索词：同义词、简称或平台常见用语，用于找到已有讨论；新场景、人群、阶段、约束或对比维度，用于发现有实质区别的问题。例如「团队协作软件怎么选」可派生「小团队项目协作 权限」「企业协作工具 数据迁移」和「已确认竞品 对比 任务分配」，并标明关联 S01。这些检索词是候选方向。
3. 第一轮覆盖不同种子的主要意图，优先让每条种子至少有一条有效查询；种子较多时可共用查询并保留映射。第二轮根据知乎原题和回答里的真实用词补搜，优先补覆盖薄弱的种子。同义改写或原题原样命中可记为验证结果，从新增问题数中排除。新问题可对应多个种子；与种子无直接关系的相关发现单独标注。

## 知乎采集与筛选

- 用同一次运行的 UUID 调用 `geo_research.search_sources`，每批最多 4 词，每词最多 8 条。在实际调用日志记录查询词、种子编号、接口状态、返回量和入选数。首轮可选 6–10 个词，第二轮根据覆盖补 4–8 个；根据目标和接口预算调整。限流后等待并低频补查一次；达到目标且覆盖主要方向、连续两个批次没有新问题，或达到平台限制时结束。
- 问答用 `question_id` 或从 `/question/<id>/answer/<id>` 提取父 ID 去重。知乎 API 返回的原题取问答记录的题干并附原问题链接。回答摘要只用于发现语境和筛选；专栏标题或文章内容支持的问题需标记归纳，不算知乎用户原题。没有原问题 ID 的条目只有在来源能证明它是问答原题时才纳入原问。
- 按对象、场景、意图和约束合并重复问题。费用、合同或报销、购买渠道属于不同意图，可分别保留。品牌或竞品只在题干出现时算点名；出现在回答或查询词中只作上下文。归纳题即使写入品牌名，也不计为平台点名原问。
