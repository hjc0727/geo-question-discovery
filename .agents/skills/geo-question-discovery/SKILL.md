## 选择入口

- **品牌发现**：只给品牌名就开始。先查品牌官网并确认主体，提取产品、服务、用户和使用场景，再查证同类竞品。用户已提供的官网、产品服务、别名和竞品直接用于缩小范围，只补缺失信息。仅给行业名时，按行业品类探索。
- **种子扩展**：用户给了行业例题、已有问题或待扩展的问题清单时，保留原题并分配编号。沿每条题的产品、场景和意图生成新检索词，优先找覆盖不同约束、阶段或使用人群的新问题。可用已有品牌资料补足语境；资料不全时按需查证。种子问题用于引导检索，从新增题计数中排除。

## 查找和整理

1. 按[检索与筛选](references/discovery.md)核实品牌资料、生成两轮查询。两种入口均调用 `geo_research.search_sources`，指定 `source=zhihu`。官网和竞品资料用于划定范围与生成词；平台原问以知乎记录核验。小红书不作为这两个入口的默认来源。
2. 优先采集知乎原题，按原问题 ID 和语义意图去重。只在有具体证据时增加归纳题，并明确标注。题干明确包含目标品牌或已确认竞品名称时才标记点名。种子扩展时进一步核对与原题的重复和差异，保留对应种子编号。
3. 按[输出协议](references/output.md)导出问题 CSV 和覆盖报告，附知乎来源链接、问题类型、品牌或竞品点名标记。品牌发现记录官网、主要产品或服务和已核实竞品。种子扩展报告每条种子的覆盖与新增情况。输出问题，不输出答案。目标条数按实际证据交付；无 API 凭据或 API 失败时说明状态，保留已查证的范围和待执行检索词。

收到验证请求时，用固定样本检查原题去重、种子关联和点名标签。需要验证真实覆盖时，再运行知乎 API 并报告实际样本。
